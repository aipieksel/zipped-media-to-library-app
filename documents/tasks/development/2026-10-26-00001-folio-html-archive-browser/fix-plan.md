## Canonical data and migration
Retain existing archive IDs, file IDs, page paths, Blob stores and snapshot page IDs. Extend the item record with an optional `kind` discriminator (`html` default for v1; `image` explicit), so old HtmlPage callers remain compatible. Images use the same `${archiveId}/${path}` identity as their file record. Upgrade IndexedDB additively to v2, create flat `folders` and `organization` stores, index image metadata from existing retained file records without reading/copying their Blob bytes. Abort on migration errors; never delete/reset a failed database. New import bundles include HTML and images, while HTML counts/tests filter by kind. Direct supported image files are bundled into a named import with the same storage/limit rules. SVG is rendered only as `<img src=blob:...>`; never inserted into parent DOM or allowed to execute as HTML.

Folders are metadata collections. `organization` maps an item ID to favorite and nullable folder ID. Folder names trim, reject empty/overlong values and duplicate names. Move validates both item and target folder, updates only organization, and keeps linked resource maps untouched. The shared organized tree has user folder groups plus unassigned archive contents. Moved items appear in their chosen folder, while archive bytes stay retained. Kind/search/favorite filters must yield the same tree, navigation and gallery set. Empty folders remain createable and visible. Remove an import cleans its items, images, captures and organization without touching unrelated roots or folders.
